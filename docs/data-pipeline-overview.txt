HKS COURSE EXPLORER DATA PIPELINE

Historical evaluations:
  data/canonical_courses_enriched.csv
    -> scripts/build_data.py
    -> public/courses.json and public/sim_coords.json
    -> static CDN assets used by the React application

Current offerings:
  Harvard ATS API
    -> scripts/sync_live_courses.py
    -> service-only atomic Supabase RPC
    -> Supabase live_courses
    -> Browser Schedule Builder

Section meeting data:
  Harvard source/section import process
    -> Supabase course_sections
    -> Browser Schedule Builder meeting-time enrichment

Safety rules:
- The canonical CSV is reviewed input; build validation rejects fatal data errors.
- Generated duplicate course IDs are reported with the conflicting IDs. They
  retain legacy last-write-wins behavior during loading and must be resolved
  before any controlled promotion.
- Any failed source request aborts a live-sync run before upsert or stale deletion.
- Harvard result pages use the documented scroll cursor. Any malformed, repeated,
  or failed page aborts the entire run before data can change.
- A complete validated source payload is upserted in one database transaction;
  a database error leaves the previously served live catalogue intact.
- Current database schema/RLS and data-retention setup still require a fully
  versioned baseline migration before a clean environment is reproducible.
